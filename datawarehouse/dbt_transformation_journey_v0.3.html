What is dbt — and where does it run?

dbt (data build tool) is a SQL-first transformation framework. It authors, tests and documents our models — then runs them inside our existing Microsoft SQL Server. The data never leaves the warehouse.

The Old World: Our Legacy Transformation Approach

Every transformation lived inside stored procedures. It ran — but it didn’t scale, and it was hard to trust and change safely.

🔒
Manual, ad-hoc versioning
Scripts versioned by hand — inconsistent history, no peer review, error-prone rollbacks.
🚫
No automated testing
Data quality issues surfaced in production, not before release.
🕷️
Hidden lineage
Dependencies buried inside procs — impact of a change was hard to trace.
🧩
Monolithic & coupled
Large, intertwined procedures — one change risked breaking many outputs.
⚙️
Manual deployments
Hand-run scripts across environments — slow, inconsistent, error-prone.
📜
Sparse documentation
Logic lived as tribal knowledge — onboarding and handover were painful.

Why We Chose dbt

Each pain point of the old world is addressed by design — without leaving SQL behind.

💻
SQL-first & familiar
Teams stay productive in SQL — low learning curve, fast adoption.
🧱
Modular models
Small, reusable, testable units replace giant procedures.
✅
Built-in tests
not_null, unique, relationships & custom tests run every build.
📈
Automatic lineage & docs
An always-current DAG and docs generated straight from code.
🌐
Git version control
Full history, code review and safe rollbacks by default.
🚀
CI/CD ready
Automated, repeatable deployments across environments.

Migration & Adoption Journey

A phased, low-risk path — rebuilt layer by layer and validated against the legacy outputs before cutover.
